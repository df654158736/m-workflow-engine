# 文档同步（Doc-Sync）

## 核心原则

> **代码是 Source of Truth** — 需求文档、详设文档必须反映当前实现状态。
> **正文只保留当前态** — 历史变更全部外置到 `.changelog.md`。
> **双向同步** — 改需求→同步详设；改实现→同步需求。任何一方偏离就更新所有关联文档。

---

## 两种模式

| | 增量同步 | 全量同步 |
|--|--|--|
| **命令** | `/doc-sync` | `/doc-sync-after-dev` |
| **时机** | 开发过程中，发现实现偏离文档时 | feature 分支完成，准备合并前 |
| **对比基准** | 当前对话中的变更决策 | `git diff main...HEAD` 全量 |
| **更新范围** | 只更新偏离的具体章节 | 扫描所有关联文档 |
| **版本号** | 递增（如 1.0→1.1） | 递增（如 1.1→1.2） |

---

## 文档格式统一规则（需求文档和详设文档通用）

### 规则 1：正文 + changelog 分离

每个文档拆成两个文件：

```
PRD-001-User-Management.md              ← 正文，只保留当前最新状态
PRD-001-User-Management.changelog.md    ← 变更日志，所有留痕集中在这里
```

### 规则 2：正文头部格式

```markdown
> **Version**: 1.2
> **Date**: 2026-04-02
> **Changelog**: [变更日志](./PRD-001-User-Management.changelog.md)
```

### 规则 3：正文章节变更标记

被变更过的章节，标题后加版本标记，标题下加一行变更摘要：

```markdown
### 3.2 分页导出 `v1.2`
> 变更: 废弃一次性导出，改为分页 `v1.2` {gitid} | [详情](./PRD-001.changelog.md#v12)
```

**变更 >3 次**：只保留最近 3 次 + 总数。
**从未变更**：不加任何标记。

### 规则 4：changelog 文件格式

```markdown
# {文档编号} 变更日志

> 关联正文: {正文文件名}

## [v1.2] 2026-04-02 | {gitid}

- **§3.2** 废弃 → 一次性导出改为分页导出 | 原因: 大数据量超时 | 替代: §3.2 分页导出

## [v1.0] 2026-03-24 | {gitid}

- 初始创建
```

| 字段 | 说明 | 必填 |
|------|------|------|
| 章节号 | `§X.X` 对应正文章节 | 是 |
| 变更类型 | 新增 / 修改 / 废弃 / 推迟 | 是 |
| 变更内容 | 具体改了什么 | 是 |
| 原因 | 为什么改 | 是 |
| 关联 | 同步更新了哪些其他文档 | 有关联时必填 |

### 规则 5：废弃逻辑处理

- **正文**：直接删除废弃内容，替换为新方案。不留删除线。
- **changelog**：记录完整的废弃信息。

### 规则 6：版本号规则

| 变更类型 | 版本递增 |
|---------|---------|
| 接口/数据模型/验收标准变更 | 次版本 +1 (1.0 → 1.1) |
| 仅描述修正/格式调整 | 修订版本 +1 (1.0.0 → 1.0.1) |
| 架构重大变更 | 主版本 +1 (1.0 → 2.0) |

### 规则 7：现有变更记录迁移

首次对一个文档执行同步时，如果文档内有旧的变更记录表格，将其迁移到新建的 `.changelog.md`。

## 增量同步模式（`/doc-sync`）

### Step 1: 识别变更

从当前对话上下文提取已确认的变更决策。

### Step 2: 定位关联文档

搜索链路：
1. 当前工作文件/模块 → 关联详设（`docs/specs/`）
2. 详设头部 `关联需求` → 需求文档（`sprints/backlog/requirements/`）
3. 反向：需求 → 所有引用该需求的详设

### Step 3: 更新文档

1. 检查是否需要迁移旧格式（规则 7）
2. 递增版本号（规则 6）
3. 更新正文为当前最新状态
4. 添加章节标记（规则 3）
5. 追加 changelog 条目（规则 4）

### Step 4: 输出同步报告

## 全量同步模式（`/doc-sync-after-dev`）

### Step 1: 收集变更信息

```bash
git branch --show-current
git log --oneline main..HEAD
git diff main...HEAD --stat
git config user.name
```

从分支名推导模块，从变更文件推导涉及范围。

### Step 2: 对比代码与文档

| 维度 | 代码中的来源 | 文档中的位置 |
|------|-------------|-------------|
| REST API | FastAPI Router 端点 | 详设 "API Design" 章节 |
| 数据模型 | Pydantic Model / SQLAlchemy Model | 详设 "Data Model" 章节 |
| 前端组件 | `.tsx` 文件、路由配置 | 详设 "组件/页面清单" 章节 |
| 配置项 | `.env` / config 文件 | 详设 "Configuration" 章节 |
| 验收标准 | 实际功能行为 | 需求文档 "验收标准" 章节 |

识别差异类型：新增 / 修改 / 废弃 / 一致

### Step 3: 更新文档

同增量模式 Step 3。

### Step 4: 清理增量标记

确认之前增量同步的标记仍然准确。

### Step 5: 更新任务文档

标注实际完成情况 vs 原计划，补充计划外新增。

### Step 6: 生成同步报告

### 增量模式 checklist
- [ ] 变更决策已从对话中完整提取
- [ ] 所有关联文档已定位（需求 + 详设，双向）
- [ ] 旧格式变更记录已迁移
- [ ] 正文版本号和日期已递增

- [ ] git diff 差异已完整扫描
- [ ] 代码与文档所有维度已对比
